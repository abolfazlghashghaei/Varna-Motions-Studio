# طرح پیشنهادی پیش از اجرای بازطراحی

این سند طرح است. هیچ‌یک از فایل‌های CSS یا ساختارهای زیر هنوز در پنل اجرا نشده‌اند. هدف، آسان‌شدن پیدا کردن و انجام کارها با حفظ قابلیت‌ها و داده‌های پروژه است.

## ۱. شکل مشترک همهٔ صفحه‌ها

ترتیب ثابت:

1. **عنوان کار**؛ مانند «متن را ویرایش کن».
2. **یک جمله دربارهٔ نتیجه**؛ مانند «واژه‌ها و زمان زیرنویس انتخاب‌شده را تغییر بده.»
3. **محدودهٔ کار**؛ متن/خانه/کامپوزیشن انتخابی و «همین مورد / همهٔ موارد» در یک جای ثابت.
4. **تنظیمات اصلی همان کار**؛ عنوان‌های کوتاه و کنترل‌های مرتبط کنار هم. مثلاً X/Y، عرض/ارتفاع و شروع/پایان از هم جدا نشوند.
5. **یک کار اصلی برجسته**؛ فقط یک دکمه یا انتخاب اصلی در هر وضعیت؛ پیش‌نمایش، بازگردانی و ذخیرهٔ استایل نقش ثانویه داشته باشند. پاک‌کردن نقش خطر دارد و رنگ اصلی نمی‌گیرد.
6. **تنظیمات پیشرفته**؛ بسته در شروع، با عنوان و کنترل باز/بستهٔ قابل‌مشاهده. مسیر مدل، نقاط منحنی، فرمول و کنترل دقیق افکت اینجا قرار بگیرند.

هدر سراسری فقط خانه/بازگشت، نام صفحه، جست‌وجو و اتصال را نشان دهد. خروجی سراسری یک میانبر ثانویه بماند؛ با کار اصلی هر صفحه رقابت نکند. مسیر «خانه ← کار ← زیربخش» قابل فهم باشد. تب‌های قدیمی هم‌زمان با دسته‌بندی جدید به‌عنوان ردیف‌های تکراری نمایش داده نشوند.

در نمای عادی، بخش اصلی فرم تمام عرض مفید را بگیرد. پنهان‌شدن پیش‌نمایش یا یک ستون نباید جای خالی آن ستون را نگه دارد. جدول و طراحی کلمه، پیش‌نمایش مرتبط خود را کنار یا بالای تنظیمات نگه دارند؛ اندازه و مختصات واقعی پروژه تغییر نکند.

## ۲. مقیاس پیشنهادی tokens

نام فایل پیشنهادی: `css/ui/tokens.css`. یک قرارداد؛ بدون نام نسخه در نام متغیر. متغیرهای قدیمی در دورهٔ مهاجرت با alias سازگار نگه داشته شوند.

| نقش | مقدار پیشنهادی |
|---|---|
| متن توضیحی، راهنما و وضعیت | ۱۲px، line-height حداقل ۱٫۶ |
| label و کنترل | ۱۳px |
| متن اصلی | ۱۴px |
| عنوان گروه | ۱۶px |
| عنوان صفحه | ۱۸px |
| فاصله | ۴، ۸، ۱۲، ۱۶، ۲۴px |
| شعاع | ۴ برای جزء کوچک؛ ۸ برای کنترل؛ ۱۲ برای کارت/modal |
| ارتفاع کنترل | عادی ۳۶px؛ فشرده هرگز کمتر از ۳۲px |
| آیکون رابط | ۱۶ یا ۲۰px؛ دکمهٔ صرفاً آیکونی با سطح کلیک حداقل ۳۲×۳۲ |
| حلقهٔ تمرکز | ۲px، با فاصلهٔ ۲px؛ در همهٔ تم‌ها قابل تشخیص |

تنظیم تراکم موجود باقی می‌ماند؛ به فاصله، تعداد ستون و فضای کارت‌ها مربوط می‌شود. کف ۱۲px برای متن رابط در هیچ حالت تراکم شکسته نمی‌شود. کوچک‌کردن کل پنل با `zoom` یا `transform:scale()` راه‌حل نیست.

این مقیاس بر **رابط** اعمال می‌شود. سایز دلخواه متن ویدیو، اعداد پروژه، فونت انتخابی کاربر، مختصات، اندازهٔ preview و تنظیمات گرافیکی خروجی تغییر نمی‌کند.

### رنگ‌های پیشنهادی

| نقش | روشن | تیره |
|---|---|---|
| زمینه | `#F1F5F9` | `#0F172A` |
| سطح کار | `#FFFFFF` | `#1E293B` |
| متن اصلی | `#0F172A` | `#F8FAFC` |
| متن کم‌اهمیت | `#475569` | `#CBD5E1` |
| کار اصلی | زمینهٔ `#1D4ED8`، متن سفید | زمینهٔ `#93C5FD`، متن `#0F172A` |
| موفقیت | `#166534` | `#86EFAC` |
| هشدار | `#92400E` | `#FCD34D` |
| خطر | `#BE123C` | `#FDA4AF` |

روی سطوح تخت انتخاب‌شده، کمترین نسبت جفت‌های متن پیشنهادی ۶٫۲۹:۱ است؛ [محاسبات](proposed-contrast.json). هنوز در محصول اجرا و روی شیشه/گرادیان/پالت سفارشی آزموده نشده است. رنگ وضعیت همواره با متن یا آیکون و متن همراه باشد، نه فقط رنگ.

سطح کنترل‌های کاری خوانا و تقریباً یکدست باشد؛ شیشه و حرکت لوگو در قاب و نوارها بماند. پالت سفارشی باید رنگ خوانای متن/دکمه را نیز محاسبه یا اعتبارسنجی کند؛ تضمین AA با رنگ نامحدود دلخواه ممکن نیست. این موضوع فقط مربوط به پالت رابط است، نه رنگ ویدیو.

## ۳. دستور زبان کامپوننت‌ها

| کامپوننت | قرارداد پیشنهادی | رفتار موجود که حفظ می‌شود |
|---|---|---|
| دکمهٔ اصلی | متن فعلیِ نتیجه‌محور؛ یک نقش اصلی در وضعیت فعال؛ عرض/ارتفاع ثابت و متن کامل | همان handler و همان عملیات |
| دکمهٔ ثانویه | سطح ساده و حاشیهٔ مشخص؛ بدون رنگ پرقدرت اصلی | پیش‌نمایش، بازگردانی، انتخاب فایل و ابزارها |
| دکمهٔ خطر | رنگ خطر با کنتراست کافی؛ فعل و موضوع روشن | محدودیت‌ها و تأییدهای فعلی حذف/بازنشانی |
| عدد + هندل + نوار | یک قاب، عدد قابل تایپ، هندل و slider با focus روشن؛ واحد کنار label | drag، یک commit در پایان، Escape، کلیدهای جهت، min/max/step، readonly و disabled |
| شروع/پایان و دو stop گرادیان | کنترل زوجی یکپارچه؛ مقدارها با ترتیب و واحد روشن | دستگیره‌های دوگانه و همگام‌سازی فعلی؛ تبدیل کور به slider تکی انجام نشود |
| سوییچ | label با معنی روشن و وضعیت «روشن/خاموش»؛ کل سطر هدف کلیک قابل‌فهم | checked/disabled و رویدادهای فعلی |
| فهرست کشویی | اندازه و حاشیهٔ یکسان؛ label واقعی و focus قابل دیدن | value و انتخاب‌های قبلی؛ هیچ مقدار داخلی ترجمه نشود |
| انتخاب فونت | نام انتخابی، جست‌وجو، نمونه، علاقه‌مندی و بستن با Escape | PostScript name، انتخاب جداگانهٔ خانه/کلمه و همان handlerها |
| کارت | عنوان کوتاه، محتوای یک کار، فاصلهٔ استاندارد | ID، classهای قراردادی و دسترسی جست‌وجو |
| وضعیت و خطا | چه شد → اقدام بعدی → جزئیات فنی جمع‌شونده | کد و گزارش فنی برای تشخیص باقی بماند |

در صفحه‌ای مانند استایل‌ها که **انتخاب کارت خودش اعمال می‌کند**، انتخاب فعلی و پیام «روی متن انتخابی اعمال شد» روشن می‌شود. دکمهٔ تأیید صوری یا تأخیر جدید به این رفتار اضافه نمی‌شود. در ویرایش متن نیز زمان commit فعلیِ blur/مکث حفظ می‌شود؛ ظاهر جدید نباید توهم وجود ذخیرهٔ جداگانه بسازد.

## ۴. متن‌ها و نام‌گذاری

| فعلی | پیشنهاد برای رابط | توضیح کوتاه در صورت نیاز |
|---|---|---|
| کپشن / متن | زیرنویس / متن انتخابی، بسته به محل | نام فنی در داده و API ثابت بماند |
| Preset | استایل آماده یا حرکت آماده | بر اساس نتیجه، نه ترجمهٔ یکسان برای همه |
| Tracking / Leading | فاصلهٔ حروف / فاصلهٔ خط‌ها | مقدار و واحد فعلی حفظ شود |
| Easing | نرمی حرکت | «سرعت حرکت در شروع و پایان را تنظیم می‌کند.» |
| Keyframe | نقطهٔ تغییر حرکت | «مقدار این ویژگی را در یک زمان مشخص می‌کند.» |
| Expression | فرمول حرکت | «کد کوتاهی که مقدار حرکت را محاسبه می‌کند.» |
| Entity Lock | نام‌های محافظت‌شده | «این نام‌ها با اصلاح خودکار تغییر نمی‌کنند.» |
| Material | جنس و ظاهر | مانند شیشه، رنگ ساده، رنگ حجمی |
| SFX / Cue | افکت صوتی / بخش صدا | صدای کوتاه یا محیطی در بازهٔ مشخص |
| Apply Preset | اعمال حرکت به متن / استفاده از این استایل | نام موضوع و محدوده در همان بخش |
| Node / Host error | پیام متناسب با علت واقعی | جزئیات فنی کنار اقدام بعدی؛ بدون حدس علت |

تمام تغییر متن‌ها باید هم‌زمان در واژه‌نامهٔ فارسی/انگلیسی ثبت شوند. نام مدل، فونت، برند، فایل، متن زیرنویس، محتوای فرمول و نام داخلی میزبان دست‌نخورده بماند. tooltip با focus کیبورد هم قابل دسترسی باشد؛ تنها title مرورگر کافی نیست.

## ۵. معماری فایل‌ها و مهاجرت

ساختار هدف پیشنهادی:

- `css/ui/tokens.css`: رنگ، فونت، فاصله، اندازه و aliasهای سازگاری.
- `css/ui/base.css`: reset محدود به پوستهٔ خود محصول، تایپوگرافی و جهت متن.
- `css/ui/components.css`: دکمه، عدد/نوار، سوییچ، select، کارت، عنوان و وضعیت.
- `css/ui/pages.css`: چیدمان خاص ۲۲ صفحه و breakpointها؛ بدون تعریف دوبارهٔ ظاهر عمومی کنترل‌ها.
- فایل‌های vendor و استایل گرافیک preview مالک جدا دارند؛ با پایهٔ رابط یکی نمی‌شوند.

این هدف به معنی ترکیب فوری ۳۱ فایل نیست. برای هر کامپوننت:

1. انتخابگرهای قدیمی و وضعیت‌هایشان ثبت شوند.
2. قرارداد جدید فقط برای همان جزء جایگزین شود.
3. مقایسهٔ تصویر و رفتار در تم‌ها/اندازه‌ها انجام شود.
4. قاعدهٔ قدیمی فقط وقتی حذف شود که نقش آن در تمام ورودی‌ها پوشش یافته باشد.

فایلی صرفاً به‌دلیل نام نسخهٔ قدیمی یا نبود match در یک اسکرین‌شات حذف نمی‌شود. `stability26.css` و `plugin53.css` نمونه‌های واقعی دلیل این احتیاط‌اند. یک فایل سی‌ودوم با زنجیرهٔ `!important` مالکیت را حل نمی‌کند. انتخاب cascade layer یا فناوری جدید نیز پس از بررسی CEF واقعی هدف انجام شود؛ تکیه بر Chromium نصب‌شدهٔ محیط آزمون کافی نیست.

برای سه ورودی، قالب مشترکِ تولیدشده در زمان build پیشنهاد می‌شود: body و اجزای مشترک از یک منبع؛ `index.html`، `premiere.html` و `resolve.html` خروجی‌های ثابت و آفلاین بمانند. اتصال اختصاصی هر میزبان و `VARNA_HOST54` حفظ شوند. کپی‌کردن adapter افتر در دو میزبان دیگر هدف این کار نیست.

طبقه‌بندی مبتنی بر متن عنوان قبل از فارسی‌سازی به metadata صریح و پایدار متصل شود؛ انتخابگرهای مبتنی بر ID/class و رفتار رویدادها با قرارداد ثبت‌شده تطبیق داده شوند. این تغییر محدود به لایهٔ ارائه است و فایل `host/ghaf_host.jsx` در بازطراحی ظاهری نیاز به تغییر ندارد.

## ۶. خانه و شروع سریع

پنج کارت اصلی پیشنهادی:

1. **زیرنویس بساز** — «صدای ویدیو را به متن تبدیل کن.»
2. **متن را طراحی کن** — «فونت، رنگ، زمینه و حرکت متن را تنظیم کن.»
3. **جدول بساز** — «جدول را روی ویدیو قرار بده و متحرک کن.»
4. **صدا آماده کن** — «موسیقی یا صدای دلخواهت را بساز و اضافه کن.»
5. **برند را انتخاب کن** — «فونت، رنگ و فایل‌های برندت را دوباره استفاده کن.»

همهٔ مقصدهای فعلی در ناوبری و جست‌وجو باقی می‌مانند؛ تنظیمات و ابزارهای تخصصی با نام روشن در دسترس‌اند. ادغام کارت خانه به معنی حذف صفحه یا قابلیت نیست.

شروع سریع سه‌مرحله‌ای، کوتاه و برای اولین ورود:

1. ویدیو یا صدای خودت را در افتر انتخاب کن.
2. زیرنویس را بساز، بررسی کن و ظاهرش را انتخاب کن.
3. زیرنویس‌ها را به کامپوزیشن اضافه کن.

این بخش یک مسیر عملی کوتاه است، نه مجموعهٔ آموزش‌های قدیمی. در استفادهٔ بعدی قابل جمع‌شدن باشد و از محل مشخص دوباره باز شود.

در مرحلهٔ ۵، متن، جدول و خروجی ابتدا به‌عنوان سه نمونهٔ حساس بررسی شوند؛ همان الگو سپس روی همهٔ ۲۲ صفحه اعمال شود. کارهای ناتمام هر مرحله ثبت شوند، نه اینکه در گزارش «کامل» حساب شوند.

## ۸. معیار پذیرش

- متن رابط کمتر از ۱۲px نباشد؛ متن اصلی ۱۳–۱۴px و دکمه‌ها حداقل ۳۲px.
- عنوان، جملهٔ نتیجه، محدوده و کار اصلی در اولین نمای قابل استفادهٔ صفحه روشن باشند.
- کنتراست متن معمولی حداقل ۴٫۵:۱؛ مرز/حالت اجزای لازم حداقل ۳:۱، همراه با بررسی متن روی شیشه و تصاویر.
- کنترل عددی، هندل، slider، Escape، تایپ، step، min/max، readonly و disabled همان رفتار فعلی را داشته باشند.
- ۸۹۹ ID ثابت و کنترل‌های پویای ثبت‌شده در سناریوها حفظ شوند؛ assertionهای فعلی دستکاری نشوند.
- iframe و ابزار افزوده بدون بررسی قراردادشان بازنویسی نشوند؛ بخش مشترک میزبان، adapter اختصاصی را تغییر ندهد.
- اندازهٔ مرجع ۶۲۰×۶۴۰ است؛ ۱۰۰۰×۷۶۰ و ۷۶۰×۵۲۰، عرض‌های آزمون موجود و DPI واقعی نیز بررسی شوند. در حداقل اعلام‌شدهٔ ۲۵۰×۲۵۰، خوانایی قربانی جا دادن همهٔ کنترل‌ها نشود: زیربخش‌های نام‌دار و راه مشخص بازکردن فضای بیشتر لازم است.
- پیش‌نمایش جدول قابل‌دیدن بماند؛ مختصات واقعی پروژه، دور گوشه‌ها و نسبت تصویر با تغییر رابط تغییر نکند.
- خاموش/روشن اصلاح آفلاین و جمله‌بندی، تأیید راست‌کلیک، اصلاح‌های قبلی، Undo/Redo، برند و دادهٔ پروژه حفظ شوند.
- تعداد و ترتیب پیام‌های بومی، شروع/لغو پردازش و عدم اجرای خودکار افکت/دانلود در اثر ورود به صفحه تغییر نکند.
